# Security Policy

Ornare treats security and user-data integrity as release-blocking requirements.

## Reporting a vulnerability

For a hosted source repository, use the repository provider's **private security advisory / private vulnerability reporting** mechanism. Do not disclose a suspected vulnerability in a public issue before a fix is available.

## Supported release policy

Only the latest publicly supported Ornare release line is expected to receive security fixes during V1. A formal multi-version servicing policy must be defined before maintaining more than one release line.

## Development requirements

See:

- `docs/SECURE_SDLC.md`
- `docs/SECURITY_PRIVACY.md`
- `docs/DEPENDENCY_SUPPLY_CHAIN.md`
- `docs/THREAT_MODEL.md`

No security finding may be suppressed solely to make a release gate pass.
